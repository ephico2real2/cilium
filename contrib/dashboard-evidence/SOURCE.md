# Fork-only dashboard evidence

The initial candidate is dashboard commit `e00be3729bf71334a500b5202a8e1136177697b3`, based on upstream `3b6e980b3d4eaa5be4532602ccb2bd54d8540dc4`. Upstream dashboard contents are unchanged at `e5967e950b8f10ae514c58787e80d8e0192c15fd`, the default baseline for subsequent runs. The evidence tools stay separate from the small proposed upstream JSON change.

The browser walk, prepared Ubuntu Playwright image, smoke tests and publication helper reuse the pattern from `ephico2real2/cilium-implementation-poc` at `22fb6e14c0cca8c78af1f072d1e89ebaea6a916b`, `.github/actions/browser-walk/action.yml`, `scripts/capture/walk.js` and `.github/workflows/demo55-ci.yaml`, as ported into CMTC at `125a937`. YAML/JSON page specs, PNGs on failures, publishing before enforcing the result, per-run folders and immutable inline run-page images are preserved. The walker additionally records real Grafana query responses and checks their totals/series counts.

The primary job builds the exact fork agent and operator, loads them into a two-node kind cluster, and deploys the matching chart and CRDs. It reuses the PoC routedemo application, Fortio 1.75.3, bootstrap and kube-prometheus-stack 90.1.1 monitoring values. The backend is pinned to the control-plane node, the Gateway Envoy and direct-pod load generator to the worker. The Gateway client is a Fortio Docker container outside Kubernetes on the kind bridge, so it has no source namespace/workload. Three six-minute loads request 200 external-to-Gateway, 200 pod-to-Gateway and 20 direct-pod HTTP requests per second. The pod Gateway client is the nonempty-source control, while the external client exercises the missing namespace/workload labels. Every stream has a separate Fortio JSON result and HTTP success/count/rate assertions. CI waits for repeated real scrapes, asserts remote backend workload labels on the worker's metrics, checks actual Grafana query responses, and retains final Fortio request counts/status codes. The reporter label is discovered from the actual Gateway series. The baseline excludes Gateway traffic and may retain direct-pod traffic; the fixed panels must include Gateway traffic. Empty fixed panels fail. Raw Hubble metrics, HTTP flows and Prometheus scrape targets are retained on failures as well.

Prometheus 3.10.0 synthetic 500/50/550 fixtures remain supplementary query tests only. No synthetic exporter runs in the deployed live-load test. Neither fixture nor live HTTP evidence establishes workload mTLS or transport encryption. CI uses plaintext HTTP deliberately to isolate the dashboard regression.

All numeric assertions, actual browser queries, Prometheus logs and screenshots are retained as a run artifact. Only screenshots and allowlisted assertion files are published to `ci-captures`. CI uses an ephemeral workflow token; no human SSH key is copied to CI.

The workflow accepts full source/baseline SHA inputs for later fork changes. Internal pull requests affecting the dashboard/evidence tools and pushes to the two evidence branches test their exact head commit. Manual runs can select another immutable source. Main merges avoid duplicate expensive runs. Build/version assertions and commit statuses use the chosen immutable SHA. The fork-only job is restricted to ephico2real2/cilium.
