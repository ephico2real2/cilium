# Ztunnel authorization protocol

The schema is copied from [cilium/ztunnel v1.0.0](https://github.com/cilium/ztunnel/blob/5bb9cf256b10a209ae9bc0624ddfbf27dbc439de/proto/authorization.proto), source commit `5bb9cf256b10a209ae9bc0624ddfbf27dbc439de`, Git blob `6c4c03c95bfc0c28e1b54230f279aa7317d5d057`. Cilium changes the Go package option and adds a provenance comment; message names, field numbers, enums and the original rule/clauses/matches semantics are preserved. The separate Go package avoids colliding with the workload protocol's Address type.

This is the protocol expected by the selected Cilium proxy source, not a copy of current Istio's policy compiler. The xDS type URL is `type.googleapis.com/istio.security.Authorization`. Importing these types does not implement policy delivery or claim ClusterMesh mTLS support. The existing compatibility guard remains intact.

Regenerate through the existing `make proto` pipeline, or use `bash pkg/ztunnel/pb/security/generate.sh` to regenerate only this schema. The focused CI workflow verifies the official protoc archive checksum and reproducible output using protoc 33.1 and protoc-gen-go 1.36.10, matching the checked-in ztunnel Go bindings; protoc-gen-go-json 1.6.0 and protoc-gen-doc 1.5.1 match the selected builder's plugin pins. Build the generators with Go 1.27.1, as in CI and the current main module: the Go formatter used by the generator changes comment formatting between toolchain versions. No existing bindings are regenerated in this patch.

Tests pin the descriptor shape, field numbers, Any type URL, independent encoded allow-policy fixture, identity/port values, presence matching and separation of workload/security Address types. These are wire-format tests, not Rust policy-engine or datapath tests. The source-to-chart-image provenance remains unverified; validate the exact runtime image before claiming enforcement interoperability.

The next patches must add real Authorization delta resource lifecycle and effective Cilium policy translation. They must separately implement a fail-closed admission hold: this proxy skips missing policy references and can allow traffic with no effective ALLOW policies. Exact principals are required for cluster-specific rules; namespace/service-account matching ignores trust domain. Preserve application-port and finer pod-label restrictions rather than allowing the HBONE tunnel port broadly.
